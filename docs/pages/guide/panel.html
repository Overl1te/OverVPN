Работа в панели

Типичный порядок: inbound → пользователь → подписка → мониторинг.

1. Создать inbound

  1. Inbounds → создать протокол
  2. Укажите tag, listen / public host и port
  3. TLS-файлы — в каталог сертификатов ядра
  4. После сохранения панель сразу применяет конфиг
validate → write → reload → verify → rollback при ошибке
Важно SING_BOX_UDP_PORT в .env должен совпадать с портом inbound'а (обычно 443).

2. Создать пользователя

  1. Users → имя, лимит трафика, срок, лимиты устройств/IP
  2. Назначьте inbound (assignments)
  3. Скопируйте subscription URL или QR
Статус Смысл
ACTIVE доступ разрешён
DISABLED выключен вручную
EXPIRED истёк срок
LIMITED квота / устройство / IP

3. Применить конфиг вручную

Config → Preview → Apply с причиной. При сбое — rollback.

4. Мониторинг

  • Dashboard — онлайн, здоровье ядра, throughput
  • Online sessions — активные сессии
  • Audit — журнал действий

5. Роли

Роль Права
OWNER полный доступ, restore бэкапов
ADMIN users / inbounds / apply / backups
READONLY только чтение

6. Бэкапы

Тип Содержимое
DATABASE pg_dump
CORE_CONFIG конфиг ядра + last-known-good
FULL БД + конфиг + метаданные
Осторожно Restore БД перезаписывает живое состояние панели.

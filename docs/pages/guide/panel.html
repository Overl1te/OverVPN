Работа в панели

Типичный порядок: прокси-нода → inbound → план → пользователь → подписка → мониторинг.

0. Прокси-нода

При обычном install локальная нода уже есть. Удалённую добавьте через Прокси → визард. Подробнее: Прокси-ноды.

1. Создать inbound

  1. Inbounds → создать протокол
  2. Выберите прокси-сервер, tag, listen / public host и port
  3. TLS-файлы — в каталог сертификатов ядра на ноде
  4. После сохранения панель сразу применяет конфиг на ноду
validate → write → reload → verify → rollback при ошибке
Важно Порт в inbound должен совпадать с опубликованным портом ядра в .env / Compose на этой ноде (например SING_BOX_UDP_PORT для Hysteria2).

2. Создать план и пользователя

  1. Plans → создать план и привязать хотя бы один inbound (иначе подписка будет пустой)
  2. Users → имя и план. Срок, лимиты и assignments берутся из плана
  3. Скопируйте subscription URL или QR
Статус Смысл
ACTIVE доступ разрешён
DISABLED выключен вручную
EXPIRED истёк срок
LIMITED квота / устройства

Лимит устройств = максимум одновременных онлайн-клиентов. Без HWID «устройство» ≈ публичный source IP. Причина отключения видна в UI (statusReason).

3. Применить конфиг вручную

Config → Preview → Apply с причиной. При сбое — rollback.

4. Мониторинг

  • Dashboard — CPU / RAM / сеть, онлайн, здоровье ядра, throughput
  • Прокси — статус нод, heartbeat, install-command
  • Online sessions — активные сессии
  • Audit — журнал действий

5. Роли

Роль Права
OWNER полный доступ, restore бэкапов
ADMIN users / inbounds / proxy / apply / backups
READONLY только чтение

6. Бэкапы

Тип Содержимое
DATABASE pg_dump
CORE_CONFIG конфиг ядра + last-known-good
FULL БД + конфиг + метаданные
Осторожно Restore БД перезаписывает живое состояние панели.

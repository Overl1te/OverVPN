Прокси-ноды

Прокси-нода — сервер с агентом и VPN-ядрами. Панель хранит список нод (ProxyServer), привязывает к ним inbound'ы и применяет конфиг через агент.

Два сценария

Сценарий Как поставить Compose profiles
Co-located (по умолчанию) overvpn install (--with-proxy) panel,proxy,singbox,xray,mtproxy
Только панель overvpn install --no-proxy panel
Удалённый прокси Визард в панели → overvpn install-proxy … proxy + ядра
Локальная seed-нода При co-install создаётся локальный ProxyServer с фиксированным id 00000000-0000-4000-8000-000000000001. Его нельзя удалить из UI.

Удалённая нода: пошагово

  1. В панели откройте Прокси → Создать (/proxy/new).
  2. Пройдите визард (5 шагов): основы → сеть → протоколы → установка → проверка.
  3. На шаге установки скопируйте команду overvpn install-proxy --panel-url … --token … --node-id ….
  4. Выполните её на сервере ноды (root/sudo, Ubuntu/Debian).
  5. Дождитесь online / heartbeat на шаге проверки.
# пример (токен и node-id выдаёт панель)
curl -fsSL https://raw.githubusercontent.com/Overl1te/OverVPN/main/install.sh -o /tmp/overvpn-install.sh
sudo bash /tmp/overvpn-install.sh @ install-proxy \
  --panel-url https://panel.example.com \
  --token '<INSTALL_TOKEN>' \
  --node-id '<PROXY_SERVER_UUID>'

Установщик remote-ноды выставляет AGENT_BASE_URL=http://<public-ip>:7700 (порт агента по умолчанию 7700, флаг --agent-port).

Связь панель ↔ агент

Направление Эндпоинты
Агент → панель /api/agent/nodes/:id/{register,heartbeat,stats,desired,apply-result}
Панель → агент POST {agentBaseUrl}/v1/apply (и status/cores/reload)

Агент слушает Bearer NODE_TOKEN. При первом старте remote-ноды допустим INSTALL_TOKEN (одноразовый) для register.

Inbound'ы и нода

  • Каждый inbound привязан к proxyServerId.
  • Порты VPN не должны пересекаться на одной ноде между inbound'ами.
  • Default inbounds при install не создаются — только вручную в UI или флаг --create-default-inbounds.
Важно Старые однонодовые инсталлы без модели ProxyServer не мигрируются автоматически — нужен свежий overvpn install.
